# 保持掌控

Agent 能做什么，每次都由你决定：命令在真正的操作系统级沙箱内运行，权限
预设决定哪些不用问就能跑，其余一切在运行前完整地摆到你面前。

## 你真正会碰的控件

### 信任提示

在 Forebrain Harness 碰一个目录之前，它会问你是否信任它。信任按项目计：
你拒绝过的项目以受限方式启动，受信任的项目启动后工作就在沙箱内进行。

### 沙箱

命令在 macOS、Linux 和 Windows 的操作系统级沙箱内运行——有界的文件系统
路径、允许与拒绝的网络域。任何模式都不会放宽沙箱允许的范围；它只决定
一次动作尝试之前是否先问你。

### `/permissions`

一条命令在预设之间切换你的审批姿态——从"只有可证明安全的命令才不问即
跑"到"任何要离开沙箱的操作都问我"。底层姿态来自 `forebrain.yaml` 的
`approval_policy`：

- `untrusted` — 只有可证明安全的命令才不问即跑。
- `on-request` — 工作在沙箱内进行；只有需要离开沙箱时才问你。
- `never` — 什么都不问；本该询问的操作一律改为拒绝。
- `granular` — 按类别逐项开关询问。

不设置是常态：被拒绝的项目以 `untrusted` 启动，受信任或尚未判定的项目以
`on-request` 启动。

### 带记忆的审批

一个动作需要审批时，你看到的正是将要运行的内容——命令、路径、网络——
回答一次即可。审批记忆把决定放在它该在的地方：一次性的留在会话作用域，
长期规则可以保存到项目或用户设置，不用永远被反复询问。

### Plan Mode

`/plan` 把调查和修改分开。Agent 先探索、再提方案；你批准计划之前什么
都不会被修改。批准计划可以放宽本会话剩余时间的询问（全部放宽，或只放宽
读和写）——刻意做成会话状态，绝不改写你配置的策略。

### 路径保护

敏感路径和秘密形态的界面受策略保护、与模式无关：读取秘密、修改宿主关键
路径、暴露凭据一律 fail closed，让意外止于意外，不升级成事故。

### 审计工作面

工具调用、审批和 run 事件都有记录、可检视——TUI 和 web UI 里每个会话的
tool audit 记录与费用汇总，让你随时能回答"它跑了什么？"。

## 各层如何叠加

自底向上一眼看全：沙箱限定命令能碰什么；权限预设决定哪些不用问就能跑；
审批把其余一切摆到你面前；路径保护和审计线索在所有这些之下运行。完整的
配置参考见[沙箱与权限](/zh/config/sandbox-and-permissions)。
